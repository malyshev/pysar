# 

## Rationale

'Auto-configured' understates the real work: upgrading a user from V4 to V3 requires a one-time backfill -- re-running their existing corpus through the hosted embeddings pipeline -- not just flipping a config flag. This is bounded, buildable engineering (not a blocker), but it's real scope that should be designed explicitly (as a migration/backfill step) rather than assumed to happen for free. Whoever eventually decides V3 as a premium addition should carry this as a named prediction/invariant, not rediscover it.
