# User docs folder as website dogfood source

## Observations

- Operator intent: add a dedicated user-documentation folder in the Pysar repo covering each aspect of using the program (install, init/hosts, pipeline stages, MCP/skills, export, troubleshooting).
- Docs must be useful and readable in-repo (not just README dump), with structure suitable to dogfood a future Pysar website documentation surface that can be read outside GitHub.
- This is direction of travel / product intent — not a binding choice of path name, IA, or static-site stack yet.

## Rationale

End-user understanding currently concentrates in README and host-specific scaffolds; a structured docs tree keeps operator/user guidance versioned with the product and avoids rewriting the same material later for a marketing/docs site. Structuring for out-of-GitHub reading from day one means the site can consume the same Markdown corpus instead of maintaining a parallel docs source.
