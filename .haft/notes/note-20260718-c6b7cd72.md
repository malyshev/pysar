# 

## Rationale

This generalizes beyond this one decision: when a reusable/generic mechanism is already decided and queued (here, the Pass/Precondition rebuild, dec-20260718-20a08f83 + dec-20260718-ffbfb04b), don't default to a cheaper hardcoded stopgap just because it's buildable sooner -- that creates intermediate technical debt that itself needs migrating, which is exactly the "heap of hardcoded scripts" failure mode the operator has been steering this project away from since the questionnaire-engine decision (dec-20260718-5570376d). Correct sequencing is: build the prerequisite mechanism first, then build the dependent feature directly against it -- skip the throwaway intermediate stage entirely, even if it means waiting.
