# 

## Rationale

A single soft prose sentence embedded in a paragraph is not a reliable enough constraint against an executing agent's own judgment, even when the exact same wording worked once (voice) and failed once (style) -- live agent behavior on identical instructions isn't fully deterministic. The generalizable lesson: for a rule that must never be violated (as opposed to a preference), state it as a standalone bolded imperative sentence, not folded into other prose, and reinforce it a second time in What-NOT-to-do. This is the same escalation pattern already used for the Bash-permission fix and the dogfood-first fix this session -- soft guidance gets tightened into an explicit, hard-to-miss rule only after a live violation surfaces it, not proactively.
