# 

## Rationale

The original tech-stack ProblemCard (prob-20260718-7d913b89) and dec-20260718-239680d4 assumed a single user installing a binary on their own machine ('handle several of his own projects'), not an operator-hosted multi-tenant service. Operator now wants to run Pysar on their own server with a web-chat interface for (presumably multiple) users -- a real, distinct deployment topology that deserves its own ADR before being built, even though it doesn't block or change today's memory-engine decision.
