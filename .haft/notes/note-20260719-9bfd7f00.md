# 

## Rationale

This corrects prior evidence attached to dec-20260718-fe926229 (evid-20260719-760410000) which verified files were written to the project-local path but didn't verify Claude Code could actually discover them there -- a real gap in what counted as "verified." Also resolves cleanly with Pysar's own architecture, not just as a workaround: a skill's prompt (how to conduct a voice conversation) is project-agnostic; only the data it produces (.pysar/voice.json) is project-scoped, and that already lives correctly under the project. One global skill install correctly serves every pysar-init'd project on the machine. Worth remembering for any future ps-* skill (e.g. ps-style): skills always install to ~/.claude/skills/, never project-local, regardless of how natural project-local scaffolding might look.
