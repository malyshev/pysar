# Full-pipeline output reaches POC-comparable voice/rigor; two concrete gaps still open

## Observations

- First true end-to-end run: intake->draft->staff-edit->sharpen->humanize->export all executed on a fresh piece (docker-for-developers-who-just-need-it-to-work-c5a3366dbe4c), confirmed via run-log.jsonl timestamps and a real exported file at PysarTest/docker-for-developers-who-just-need-it-to-work-c5a3366dbe4c.md -- the /ps orchestrator and export tool work end to end in practice, not just in tests.
- Voice/polish parity: Pysar's humanize.md reads at the same plain-spoken, concrete-example register as the POC's finished article.md -- comparable sentence rhythm, no filler, real worked examples (layer-cache mechanics, alpine/musl vs glibc, HEALTHCHECK vs no-healthcheck). This is not a first-draft-vs-finished-artifact mismatch like the earlier draft-only comparison (note-20260726-15549726) -- both sides here are fully polished outputs.
- Staff-edit caught a real fabricated statistic mid-pipeline: per staff-edit-changelog.md, it replaced an invented, unsourced timing figure ('a ten-second rebuild vs a two-minute one') with a plain qualitative description, since no source grounded a specific number. This is the technical-sanity check working as designed, not a cosmetic edit.
- Real factual error survived all the way to the final humanize.md: 'A HEALTHCHECK instruction tells an orchestrator like Kubernetes or Docker Swarm how to ask your container...' -- Docker Swarm does consult a Dockerfile's HEALTHCHECK; Kubernetes does not (kubelet uses its own liveness/readiness/startup probes defined in the Pod spec and ignores the image's built-in HEALTHCHECK). Staff-edit's own 'technical sanity' check (staff-edit-changelog.md) did not catch this -- it caught the fabricated timing number but not this orchestrator-behavior claim.
- Citation-invisibility gap from note-20260726-15549726 reconfirmed, not fixed: sources.md shows 2 real fetched Docker-docs sources whose content clearly grounds specific claims in humanize.md (the USER/sudo TTY guidance, multi-stage size reduction) -- but humanize.md has zero [^shortname] markers (grep confirmed). internal/intake/bundle.go's Source struct (line 55-58) still has only {URL, Note}, no Shortname, so an intake-grounded fact still has no mechanical path to becoming a visible citation even after the full pipeline runs.
- Scope divergence is a deliberate brief choice, not a defect: Pysar's brief.md explicitly lists 'Not a Docker Compose or Kubernetes orchestration guide' as a non-goal, so the absence of POC's Compose/Postgres section is intentional scope, not a missed capability.
- No research pass ran in this pipeline run (run-log.jsonl shows intake, draft, staff-edit, sharpen, humanize, export only) -- intake's own targeted grounding (2 sources) covered this piece's technical claims instead, consistent with research being optional/folded into intake per dec-20260725-35fa2d24.

## Rationale

Verdict: this part of the tool (the authoring pipeline through /ps) is close to done but not unconditionally done. Voice and structural quality are genuinely at parity with the hand-built POC's finished article -- the editorial passes are doing real, non-cosmetic work (staff-edit caught a fabricated number). But two concrete, checkable gaps remain open, both pre-existing rather than newly introduced: a technical-accuracy miss (Kubernetes/HEALTHCHECK) that the technical-sanity check didn't catch, and the long-standing citation-invisibility gap where real fetched sources never surface as reader-visible attribution. Calling the pipeline "done" should wait on deciding whether to address either gap (harden staff-edit's technical-sanity check scope, and/or give intake.Source a Shortname) or explicitly accept them as known limitations.
