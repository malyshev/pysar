# Solutions for: Pysar motherhome at getpysar.com: site/ Next static + Cloudflare Pages

Problem: prob-20260808-72fab46c

## Variants (5)

### V1. Isolated site/ package + GHA Direct Upload (recommended shape)

site/ owns package.json, Next 16 App Router, Tailwind 4, shadcn, output:export → site/out. Workflow path-filters site/** + workflow file; Node 22 + pnpm in site/; wrangler pages deploy site/out with CLOUDFLARE_* secrets. Build-time ingest of ../docs (frontmatter) into /docs routes. Marketing pages (/, /install CTA, maybe /docs index) use siteConfig + metadata helpers + JSON-LD. GoReleaser untouched.

**Strengths:**
- Maximizes split from Go tool source
- Matches verified static Pages Direct Upload pattern
- Preserves docs/ single-corpus invariant via ingest

**Novelty:** Package boundary is a directory-owned Node app inside a Go repo — CI working-directory isolation — not a root Next app and not a CF-built SSR worker.

**Weakest link:** docs/ path is outside site/; relative ingest and CI checkout must stay in sync or doc routes silently empty/wrong.

**Risks:**
- Two package ecosystems in one repo (Go + Node)
- Path filters must include docs/** if doc pages rebuild from docs changes

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Establishes motherhome + deploy + SEO spine; later can add preview deploys, richer marketing, or MDX features without relocating the package.

### V2. Root pnpm workspace wrapping site/

Add root package.json + pnpm-workspace including site/. Shared scripts/tooling at root; Next app still under site/src. CI installs from root. Closer to a JS monorepo shape.

**Strengths:**
- Easier shared JS tooling later
- Familiar monorepo DX if more packages appear

**Novelty:** Moves Node authority to the repo root (workspace) even while source stays under site/ — different ownership of lockfile and CI cache keys.

**Weakest link:** Root Node files blur the Go-vs-site split the operator asked for and risk tooling noise next to go.mod.

**Risks:**
- Violates spirit of solid split if root becomes JS-centric
- Larger blast radius on .gitignore and contributor onboarding

### V3. Cloudflare Git-integrated Pages build (no GHA upload)

Connect repo to Cloudflare Pages Git integration; CF runs pnpm build in site/ and publishes. Domain and project still on Cloudflare.

**Strengths:**
- Fewer GitHub secrets for Pages token
- CF-native previews

**Novelty:** Build authority moves to Cloudflare's builder instead of GitHub Actions uploading out/.

**Weakest link:** Lint/test gates and secret/env parity with Go CI become split-brain; harder to keep the same verify-out/ checklist as the verified GHA pipeline.

**Risks:**
- Diverges from verified Direct Upload how-to
- Less control over Node/pnpm versions and artifact checks

### V4. Marketing-only site/; docs stay GitHub-only

Thin landing under site/ with install CTA linking to GitHub docs/. No ingest of docs/ into the site. Fastest motherhome.

**Strengths:**
- Smallest MVP surface
- No docs path coupling

**Novelty:** Separates motherhome from documentation hosting entirely — marketing shell only.

**Weakest link:** Breaks the dual-use intent of dec-20260808-journey-docs-corpus (docs ready for site ingest) and leaves getpysar.com thin for SEO topical depth.

**Risks:**
- Conflicts with active docs decision dual-use
- Weaker organic landing beyond brand query

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Could ship a landing first, then add docs ingest as a second commission without changing hosting.

### V5. OpenNext / Workers SSR adapter on Cloudflare

Use Cloudflare's Next adapter / Workers for SSR or hybrid rendering instead of static export.

**Strengths:**
- Future dynamic routes/API without second platform

**Novelty:** Runtime kind change: Node-like or Worker SSR vs pure static HTML on Pages.

**Weakest link:** Operator and verified approach require static export; SSR adds adapter lock-in and ops complexity with no MVP requirement for dynamic server features.

**Risks:**
- Contradicts stated static + Pages Direct Upload approach
- Harder rollback and SEO determinism
