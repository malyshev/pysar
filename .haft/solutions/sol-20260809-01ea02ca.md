# Solutions for: /ps has no opt-in to make full research a mandatory pipeline stage after intake

Problem: prob-20260809-068f64df

## Variants (5)

### V1. Skill-prose --research flag mirroring --seo

Extend ps/SKILL.md (and plugin mirror): add --research to argument-hint and description; change the fixed chain to intake → [ps-research if --research] → draft → …; flip the explicit 'do not invoke /ps-research' ban into a conditional MUST when the flag is present and a MUST-NOT when absent. Step 1 resume: if --research and sources.md already indicates research_mode full (or save_research_bundle already succeeded), skip re-research like seo.md skips re-seo; if flag set and research missing before draft, insert research. docs/pipeline.md gets a --research row next to --seo. Zero Go/MCP changes.

**Strengths:**
- Minimal blast radius; matches existing flag pattern
- Reuses /ps-research verbatim via Skill tool
- High reversibility — delete flag wording

**Novelty:** Same surface contract as --seo/--review already shipped — pure orchestrator prose, no new enforcement substrate.

**Weakest link:** Enforcement is agent-prose only; an executing agent can still skip research the same way it skipped grounding in dogfood, because nothing machine-checks the stage ran.

**Risks:**
- Soft MUST may fail under model pressure to finish chain
- Resume semantics for targeted vs full research need careful wording

### V2. Skill flag plus MCP draft precondition

Same --research skill flag and chain insertion as V1, plus a hard gate: when the piece (or invocation) is marked research-required, save_draft_bundle rejects until research_mode is full / sources.md meets the research skill's bar. /ps sets the mark when --research is present (e.g. via intake metadata or a small MCP arg). Draft cannot land without research having succeeded.

**Strengths:**
- True MUST when flag set — save fails closed
- Aligns with existing save_*_bundle enforcement style
- Dogfood failure mode (skip research, invent claims) becomes harder

**Novelty:** Moves MUST from prose into the save boundary — the same place other bundle contracts are already enforced server-side.

**Weakest link:** Requires Go MCP + schema + tests; couples draft save to research policy; risk of false blocks on resume/legacy pieces that used targeted research legitimately.

**Risks:**
- Larger change set; need clear legacy/resume rules
- Does not by itself stop fantasy in intake brief before research runs

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Opens a general 'stage preconditions' pattern for later product-capability grounding gates without inventing a second orchestrator language.

### V3. Separate /ps-grounded orchestrator skill

Leave /ps research-free. Ship a sibling skill (e.g. /ps-grounded or /ps-with-research) whose fixed chain is intake → research → draft → … with the same review/seo flags. Operators who want mandatory research use the other entry point; --research on /ps is not added.

**Strengths:**
- Zero ambiguity on default /ps
- Can harden the grounded skill without touching autopilot defaults

**Novelty:** Splits entry points instead of conditionalizing one chain — avoids editing the 'research deliberately excluded' contract on /ps.

**Weakest link:** Two nearly identical orchestrators drift; operators type /ps by habit and miss research; does not match the operator's stated '--research on /ps' surface.

**Risks:**
- Discoverability failure — wrong skill chosen
- Duplication of Step 0/1/2/4/5 prose

### V4. Always-on research inside /ps (no flag)

Change default /ps chain to always run ps-research after intake. Remove the deliberate exclusion. No --research needed.

**Strengths:**
- Maximum grounding for every piece
- No flag to forget

**Novelty:** Removes the opt-in entirely — grounding becomes a universal pipeline cost.

**Weakest link:** Violates the framed constraint that default /ps stays research-free; adds latency and web-permission friction on every run (touches parked web-permission problem).

**Risks:**
- Breaks existing 'fast autopilot' contract
- Permission-prompt cost on every host
- Overkill for opinion/voice pieces that need no web research

### V5. Brief-frontmatter requires_research set by flag; draft skill owns the gate

/ps --research tells intake (or /ps after intake) to persist requires_research: true on the piece. /ps still invokes ps-research when the flag is set, but the durable contract lives on the piece: ps-draft (and any future writer) refuses to proceed without full research regardless of how the operator entered (standalone /ps-draft vs /ps). Flag is the trigger; artifact metadata is the memory.

**Strengths:**
- Resume-safe across sessions
- Standalone /ps-draft cannot bypass a marked piece
- Matches 'MUST after intake' while surviving partial runs

**Novelty:** Separates orchestration trigger (--research) from durable piece policy (frontmatter), so resume and non-/ps paths share one gate.

**Weakest link:** Needs intake/bundle schema for the new field and draft-skill + MCP agreement; more moving parts than V1 for the same user-visible flag.

**Risks:**
- Schema + skill dual maintenance
- Confusion if flag set mid-resume on unmarked piece

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Piece-level policy is the natural place to later add product-capability grounding requirements without teaching every orchestrator flag.
