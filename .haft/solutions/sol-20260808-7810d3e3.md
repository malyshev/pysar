# Solutions for: Agent-discoverable install instructions on getpysar.com

Problem: prob-20260808-cabd5795

## Variants (5)

### V1. Canonical /llms.txt index + agent instructions

Serve https://getpysar.com/llms.txt per llmstxt.org: H1, one-line summary, 'Instructions for LLM Agents' block that says on 'install' fetch install.sh / docs/install and run curl|bash then pysar init for the detected host, plus curated absolute links to /docs/install, /docs/init, GitHub. Optionally mention in robots.txt comments. Static file in site/public.

**Strengths:**
- Matches llmstxt.org convention
- Tiny static file, easy to ship on Pages
- Can encode host-specific init flags once

**Novelty:** Uses the emerging web-standard discovery path agents already know to probe, not a Pysar-invented URL.

**Weakest link:** Hosts may not auto-fetch /llms.txt from a pasted homepage URL; user may need the agent to browse or we still depend on the agent deciding to look there.

**Risks:**
- Convention adoption uneven across Cursor/Codex/Claude
- Drift if instructions duplicate docs/install.md by hand

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Establishes the discovery root; later playbooks and full dumps can hang off the same index without renumbering URLs.

### V2. Single fetchable AI install playbook (/ai/install.md)

Publish one imperative markdown playbook at a fixed URL (e.g. /ai/install.md or /install.agent.md) written as agent steps: detect host, curl install.sh, verify pysar --version, run pysar init --claude|--cursor|--codex, confirm MCP/skills. Homepage and docs link to it; optional one-line pointer from /llms.txt.

**Strengths:**
- Maximum clarity for the exact UX trick
- Easy to smoke-test as a contract
- Can stay short and host-aware

**Novelty:** Optimizes for the 'install' utterance as a procedure, not a docs index — the carrier is a runbook, not a sitemap.

**Weakest link:** Non-standard path: agents that only know /llms.txt or scrape HTML may never find /ai/install.md unless something points them there.

**Risks:**
- Invented URL with weak organic discovery
- Second document to keep aligned with docs/install.md

### V3. Raw markdown export of journey docs at stable URLs

Ship docs as agent-friendly .md (or .md.txt) alongside HTML — e.g. /docs/install.md serves the same content as docs/install.md in-repo. Agents that fetch the docs URL or follow links get clean markdown instead of Boxsi HTML chrome. No new instruction dialect; improve fetchability of the existing corpus.

**Strengths:**
- Single source of truth with journey docs decision
- Useful beyond install (all docs become agent-readable)
- Low conceptual novelty risk

**Novelty:** Changes the carrier of existing truth (markdown vs HTML), not inventing a parallel instruction product.

**Weakest link:** Does not tell the agent what to do on bare homepage + 'install'; still needs a discovery hint from HTML or another index.

**Risks:**
- Next static routing for dual HTML+md needs build work
- Homepage drop still may not reach /docs/install

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Makes /llms.txt and playbooks cheaper later because linked pages are already LLM-clean.

### V4. Homepage / HTML-first signals (meta, visible AI block, JSON-LD)

Put machine-oriented install steps in the HTML the agent gets when it fetches the pasted URL: e.g. <link rel="llms-txt">, meta ai-instructions, a small 'For AI agents' section with the curl command and init flags, optional JSON-LD SoftwareApplication. Relies on the agent reading the homepage body first.

**Strengths:**
- Matches the literal UX (URL drop = homepage fetch)
- No need for agents to know /llms.txt

**Novelty:** Co-locates instructions with the exact URL the user drops — zero second-hop discovery if the agent fetches the page.

**Weakest link:** HTML noise/token bloat and design pressure; many agents summarize marketing pages poorly and may miss a footer block.

**Risks:**
- Conflicts with clean marketing UI
- Fragile against host scrapers that truncate

### V5. Host skill/plugin install via marketplace (not site text)

Skip site-visible AI text as the primary mechanism; distribute a Cursor/Claude/Codex skill or plugin that users install from the host marketplace, with getpysar.com only as human marketing. 'install' in-chat would invoke the packaged skill, not site discovery.

**Strengths:**
- Best execution once installed in the host
- Aligns with existing ps-* skill packaging

**Novelty:** Moves the instruction out of the website into the host's skill distribution channel.

**Weakest link:** Breaks the stated trick (URL drop alone); requires prior skill install or marketplace discoverability we do not control.

**Risks:**
- Does not satisfy URL-drop UX
- Per-host packaging and review lag
- Gemini/Codex channels differ
