# Solutions for: Codex MCP auto dial still prompts for unannotated pysar tools

Problem: prob-20260808-2edd57d2

## Variants (3)

### V1. Ship default_tools_approval_mode = approve

Change assets/codex/config.toml from auto to approve — Codex skip-review dial for MCP tools. Refresh via init --force.

**Strengths:**
- One-line fix
- Matches Codex source semantics for Approve
- Matches Haft operator pattern for pre-allow

**Novelty:** Uses approve (skip-review), not auto (risk-annotation gate)

**Weakest link:** ARC/guardian may still interrupt approved tools on some Codex builds

**Risks:**
- Naming is confusing vs English 'approve'
- Does not teach Codex read vs write risk

### V2. Emit MCP tool annotations only; keep auto

Add readOnlyHint/destructiveHint on pysar tools so auto can skip reads; writes may still prompt

**Strengths:**
- Honest risk signaling
- Works with writes mode later

**Novelty:** Fixes risk model at MCP metadata, not TOML dial

**Weakest link:** Save tools still prompt under auto unless marked non-destructive; Claude parity incomplete

**Risks:**
- Larger Go change
- Does not alone match Claude allow-all for saves

### V3. approve dial + honest annotations

Ship approve for Claude-parity now and add annotations so future writes/auto modes are accurate

**Strengths:**
- Stops prompts and improves future modes

**Novelty:** Combines packaging dial with metadata honesty

**Weakest link:** Bigger blast than needed to stop prompts today

**Risks:**
- Scope creep vs operator ask to solve prompt issue
