# Solutions for: intake.Degenerate rejects non-English ideas as garbage

Problem: prob-20260809-976cff71

## Variants (5)

### V1. unicode.IsLetter + keep Fields>=2

Replace ASCII a-z range with unicode.IsLetter for the letters<3 check. Keep empty, rune-count<3, and single Fields token rules. Add Cyrillic/Ukrainian multi-word regression tests. Document that no-space CJK single-token ideas still need spaces or draft entry until a follow-up.

**Strengths:**
- Tiny diff
- Matches decision intent for lettered scripts
- High reversibility

**Novelty:** Minimal surgical fix to the proven false predicate; no new tokenization theory.

**Weakest link:** Japanese/Chinese without spaces still fail the Fields==1 rule — only partially solves 'non-English'.

**Risks:**
- Incomplete for scriptio continua

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Unblocks Cyrillic/space-separated scripts immediately; CJK can be a second decide.

**Diversity role:** minimal correct letters

### V2. unicode.IsLetter + rune budget instead of Fields

Count unicode letters; drop the single-whitespace-field rule. Treat as non-degenerate when unicode letter count >= N (e.g. 8–12) OR Fields>=2 with letters>=3. Rejects empty/short; allows long single-token CJK ideas.

**Strengths:**
- Fixes CJK and Cyrillic in one shot
- No space dependency

**Novelty:** Changes the 'idea is a sentence' proxy from whitespace words to letter mass — KIND change in mechanical heuristic.

**Weakest link:** Long gibberish single tokens (asdf×20) may pass unless a separate entropy/repeat check is added; threshold N is arbitrary.

**Risks:**
- Threshold tuning
- Gibberish leakage

**Diversity role:** script-agnostic mass

### V3. Remove letter-script check; empty/short/Fields only

Delete the ASCII/letter count entirely. Degenerate = empty OR runeCount<3 OR Fields==1. Relies on agent judgment for semantic gibberish of multi-word nonsense.

**Strengths:**
- Simplest
- No script bias

**Novelty:** Gives up on letter-script detection as a server concern — aligns with comment that semantic emptiness is agent-side.

**Weakest link:** Multi-word Latin gibberish ('foo bar baz') and multi-word Cyrillic nonsense both pass mechanical gate.

**Risks:**
- Weaker mechanical filter than today for English gibberish pairs

**Diversity role:** minimal gate

### V4. Unicode letters + Unicode word split (not only Fields)

Use unicode.IsLetter for letter count; for 'single word' detection use a splitter that treats CJK ideographs / kana runs as words (e.g. segment on IsSpace OR script/category boundaries), not only ASCII whitespace Fields.

**Strengths:**
- Addresses both ASCII bias and Fields bias

**Novelty:** Proper multilingual tokenization for the single-token rule instead of Latin-space bias.

**Weakest link:** Homegrown segmenter can be wrong; pulling ICU/segmenter adds dependency weight for a tiny gate.

**Risks:**
- Complexity vs bug size
- Deps or hand-rolled bugs

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Correct long-term shape if non-spaced scripts become a first-class author base.

**Diversity role:** i18n tokenization

### V5. Skill-only: tell agent to ignore Degenerate / pad Latin

No Go change. Instruct ps-intake to rephrase non-English ideas with Latin tokens or use entry_mode=draft to bypass. Or document the bug as known.

**Strengths:**
- Zero binary change

**Novelty:** Workaround on the agentic surface instead of fixing the false mechanical predicate.

**Weakest link:** Authors writing Ukrainian still hit MCP errors; skills cannot make false Degenerate return false — only dodge. Violates 'no skill-only sole fix' constraint spirit.

**Risks:**
- Leaves product broken for non-English

**Diversity role:** non-fix control
