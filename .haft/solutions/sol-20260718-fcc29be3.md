# Solutions for: Next implementable slice after editorial seam + init tests

Problem: prob-20260718-50c2a0f8

## Variants (5)

### V1. Real Claude init scaffold (files, not empty mkdir)

Make pysar init --claude write a minimal real host project (e.g. CLAUDE.md stub, .mcp.json or piece layout) so the already-shipped host-flag command becomes manually useful. Stays inside dec-20260718-8278c494; does not touch Pass/Run wiring yet.

**Strengths:**
- Immediately manually testable via go install + pysar init
- Uses already-accepted host-flag decision
- High reversibility

**Novelty:** Closes the product gap at the console edge the operator already installs and runs, instead of deepening unused internal packages.

**Weakest link:** Scaffold contents are under-specified — wrong file set becomes thrash or premature host-convention lock-in before piece artifact layout exists.

**Risks:**
- Guessing Claude project layout without a small frame
- Scope creep into Cursor/Codex before Claude is real

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Gives a real on-disk project root later slices (run-log, memory index, piece State persistence) can attach to.

**Diversity role:** console product completion

### V2. Wire CLI into editorial.Run (status/check stub command)

Add a thin console subcommand that loads or fabricates a piece State and runs Check/Run against registered passes (e.g. show what would be blocked), proving the Pending Pass/cycle decisions at the binary edge and raising their measure toward accepted.

**Strengths:**
- Directly attacks Pending R_eff on dec-ffbfb04b / dec-20a08f83
- Manual test: invoke command, see PreconditionError messages

**Novelty:** Makes the internal/editorial seam operator-visible without implementing LLM editorial bodies.

**Weakest link:** Without persisted piece state on disk, the demo is toy-like and may not satisfy decision predictions that assume real passes over real piece progress.

**Risks:**
- Inventing piece-on-disk layout without framing
- CLI surface naming collision with future agentic ps-*

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Forces the State persistence / piece-root questions early, which unblock run-log and real passes.

**Diversity role:** mechanism visibility

### V3. Implement per-piece run-log (dec-6ba897d4)

Add append-only structured run-log in the artifact/state layer and hook editorial.Run to append on successful pass execution, plus the voice-lock-before-packaging guard named in that decision.

**Strengths:**
- Decision already bound; clear acceptance in DRR
- Composes with existing Run()

**Novelty:** Observability-first slice — ships accountability before more passes exist.

**Weakest link:** Run-log without real passes or persistence path is mostly schema; voice-lock guard needs packaging semantics that barely exist yet.

**Risks:**
- Overbuilding log format before piece FS layout
- Partial measure again if nothing real appends

**Diversity role:** artifact-layer accountability

### V4. Implement TF-IDF memory index (dec-404573a2)

Build the classical local statistical similarity memory engine with per-project isolation and on/off toggle, starting against a tiny fixture corpus — advances the in-progress memory ProblemCard.

**Strengths:**
- Decision + problem already active
- Pure Go, no ML deps

**Novelty:** Leaves the editorial seam alone and starts the other major decided product capability (cross-piece continuity).

**Weakest link:** Needs piece corpus and index storage location; without real piece files from init/scaffold, it is hard to manually dogfood.

**Risks:**
- Parallel track while editorial seam still stub-only
- Manual test friction without projects on disk

**Diversity role:** memory product track

### V5. Install agentic ps-* / /ps harness surface (dec-a2a24f32)

Author host-agent skills/slash commands for the ps-* naming convention (Claude Code first), separate from the pysar console binary — naming already decided; command list still open so start with a minimal /ps status or init-adjacent skill.

**Strengths:**
- Matches product dual-surface design
- Claude host already named as v1

**Novelty:** Opens the author-surface/agentic path instead of more console Go.

**Weakest link:** Command list was explicitly deferred — inventing commands now reopens scope; little Go code to go install for console testing.

**Risks:**
- Not what go install loop tests
- Easy to over-enumerate commands

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Establishes where agentic tools live so later editorial passes can be invoked from chat, not only CLI.

**Diversity role:** harness-surface track
