# Solutions for: Template application flow: skip per-field walkthrough, fine-tune only on re-run

Problem: prob-20260719-9acf5faf

## Variants (3)

### V1. Single combined show-and-confirm step

When a template is picked, skip individual field-by-field questions entirely. Show the whole template's profile at once (all fields/rules and goldens in readable form) and ask one overall question: 'Use this as-is, or is there anything you'd like to change before I save it?' Handle any requested changes conversationally within that same step -- never return to a per-field walkthrough. Then save.

**Strengths:**
- Matches the operator's literal request exactly: no reconfirming each point
- Reuses Step 4's existing 'show the full profile, ask to confirm' pattern -- no new interaction shape invented
- Fine-tuning stays available exactly where the operator wants it: re-running the skill later via Step 1's already-correct re-tune flow

**Novelty:** Collapses Step 1a (offer) and Step 4 (confirm) into one fast path specifically for the template-selected branch, while the blank-conversation branch keeps its existing full walkthrough (Steps 2-4) unchanged.

**Weakest link:** If the author says 'change the tone a bit' with no further detail, the agent must judge how much clarifying follow-up is appropriate without sliding back into a full re-interview -- a real but bounded judgment call, not a structural gap.

**Risks:**
- A rushed 'looks good' confirmation could let a template apply with a field the author didn't actually notice was wrong -- mitigated by showing the full profile before asking, not after

### V2. Zero-confirmation auto-save

Selecting a template saves it immediately with no review step of any kind -- the fastest possible path, included as the floor this problem's own safety constraint rules out.

**Strengths:**
- Zero friction, trivially matches 'don't want to reconfirm' taken to its extreme

**Novelty:** Tests the boundary the operator's own established invariant already forbids -- included to make explicit why it's rejected, not a genuine contender.

**Weakest link:** Directly violates the already-established What-NOT-to-do rule in both skills: never silently adopt a template's fields without the author actually confirming them.

**Risks:**
- An author could end up with a saved profile they never actually reviewed, discovering a mismatch only later

### V3. Opt-in per-field review

Before doing anything else, ask one meta-question: 'Want to walk through each field, or just apply this as-is?' Branch to either the current full per-field flow or a fast single-confirm path based on the answer.

**Strengths:**
- Never forces either interaction shape on an author who might want the other one on a given day

**Novelty:** Preserves both existing and requested behavior as explicit author choices rather than replacing one with the other.

**Weakest link:** Adds an extra decision point the operator did not ask for and appears to specifically want to avoid ('I don't want to tune it or reconfirm each point') -- optimizes for flexibility nobody requested at the cost of the one thing that was requested: less friction.

**Risks:**
- Directly reintroduces the friction the operator is asking to remove, just gated behind one extra question first
