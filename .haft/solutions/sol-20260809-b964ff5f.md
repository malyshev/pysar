# Solutions for: Ship Pysar as a Cursor Marketplace plugin so authors connect via Customize Connected

Problem: prob-20260809-d4ae8601

## Variants (5)

### V1. In-monorepo Cursor Plugin package (skills+MCP), binary preinstalled

Add a dedicated plugin directory in the Pysar repo (e.g. plugins/pysar/) with .cursor-plugin/plugin.json, skills/ synced from the host-neutral corpus, mcp.json pointing at ${userHome}/.local/bin/pysar, logo, and plugin README. Dogfood via ~/.cursor/plugins/local, then submit the public repo (or plugin path via marketplace.json) to Cursor. pysar init --cursor keeps project scaffold but stops double-installing skills once the plugin is the Cursor skill carrier — or documents plugin as primary Cursor path.

**Strengths:**
- Matches official Cursor Plugin + multi-plugin template
- Reuses existing skill corpus and MCP dialect
- Single repo for CLI+plugin versioning

**Novelty:** KIND=packaging-in-product-repo: marketplace carrier lives beside the Go CLI in one repo, not a separate distribution product.

**Weakest link:** Author still must install the pysar binary before the plugin MCP can spawn; Marketplace listing alone does not complete the cold path if binary missing.

**Risks:**
- Skill dual-home drift if init still syncs to ~/.cursor/skills
- Submitting whole monorepo may confuse reviewers unless marketplace.json isolates the plugin source
- External Cursor review latency

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Establishes the official Cursor Plugin shape and submission path; later variants can swap MCP launch (shim, remote) without redoing marketplace review packaging.

**Rollback:** Delete plugins/ package; leave init --cursor as sole Cursor path.

### V2. Separate public plugin repo vendoring skills+MCP

Create malyshev/pysar-cursor-plugin (or similar) containing only the Cursor Plugin package. CI or release sync copies SKILL.md + mcp.json + logo from the main repo. Marketplace submission points at the thin repo. Main repo keeps init --cursor for non-marketplace authors.

**Strengths:**
- Cleaner reviewer surface (no Go/site/haft noise)
- Clear product boundary for marketplace
- Can version plugin independently

**Novelty:** KIND=distribution-boundary: marketplace artifact is a different repository/product surface from the CLI monorepo.

**Weakest link:** Sync lag between skill corpus and plugin repo — marketplace can ship stale skills while CLI releases move.

**Risks:**
- Two-repo release discipline cost
- Still requires preinstalled binary for MCP
- Init vs plugin dual-path confusion for authors

**Rollback:** Archive plugin repo; unpublish marketplace listing if live.

### V3. Marketplace plugin with install shim that ensures binary then serves

Same Cursor Plugin packaging as V1/V2, but mcp.json launches a plugin script (scripts/pysar-mcp.sh) under ${PLUGIN_ROOT} that ensures ~/.local/bin/pysar exists (download via getpysar.com/install.sh or refuse with one clear message) then execs pysar serve. Aims for Marketplace-first cold path with fewer prerequisite steps.

**Strengths:**
- Closest to acceptance for non-developer authors
- Still uses stdio local MCP (no hosted MCP rewrite)
- Can degrade to 'run install.sh once' with one message

**Novelty:** KIND=runtime-bootstrap: plugin owns binary acquisition/spawn, not only MCP wiring.

**Weakest link:** Network install from a plugin MCP spawn is brittle (permissions, offline, Cursor sandbox, review scrutiny) and can fail noisily on first tool call.

**Risks:**
- Marketplace security review may reject auto-download shims
- Harder to golden-test across OSes
- May violate 'no secrets/network surprises' expectations

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** If accepted by Cursor review and reliable on Dock-launched Cursor, removes the largest remaining cold-path gap after Connected discoverability.

**Rollback:** Fall back to mcp.json command=${userHome}/.local/bin/pysar without shim.

### V4. Install-link / deeplink distribution without Marketplace listing first

Ship a first-class Cursor install-link (deeplink) that registers the Pysar plugin or MCP into Customize Connected without waiting for Marketplace review. Package shape can still be a local/plugin directory, but distribution is link-based from getpysar.com / init stdout. Marketplace submission deferred as a follow-on.

**Strengths:**
- Unblocks dogfood without Cursor review queue
- Aligns with Phase A V5 deeplink learning
- Same package can later submit to Marketplace

**Novelty:** KIND=distribution-channel: prioritize Cursor install-link UX over Marketplace catalog listing.

**Weakest link:** Install-link formats and Connected visibility are Cursor-version-sensitive; if the deeplink only toggles project MCP, it fails the Connected-plugin discoverability goal that motivated Phase B.

**Risks:**
- May not appear as 'Plugin MCP' in Connected
- Weaker discovery than Marketplace browse
- Docs must carefully distinguish link vs listing

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Validates packaging + one-click enable before spending review lead time; can graduate to Marketplace listing with the same package.

**Rollback:** Keep Phase A printed enable locus; drop broken deeplink.

### V5. Skills-only Marketplace plugin; MCP stays init/user mcp.json

Publish a thin Cursor Plugin that only packages ps-* skills (and logo/README). Authors still get MCP via pysar init --cursor / user mcp.json. Marketplace improves skill discovery but does not make pysar appear as a Connected plugin MCP.

**Strengths:**
- Smallest packaging surface
- Avoids binary-spawn issues in plugin MCP
- Fastest possible Marketplace skills listing

**Novelty:** KIND=component-split: marketplace carries skills only; MCP remains outside the plugin.

**Weakest link:** Fails the Connected-plugin discoverability goal that Phase B and this ProblemCard target — skills install does not fix MCP Connected listing.

**Risks:**
- Does not satisfy acceptance (MCP via plugin enable)
- Splits author mental model further
- Looks like progress while leaving the cold-path gap

**Rollback:** Unpublish skills-only plugin; restore init-only skill sync story.
