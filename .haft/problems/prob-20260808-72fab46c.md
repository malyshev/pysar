# Pysar motherhome at getpysar.com: site/ Next static + Cloudflare Pages

## Signal

Pysar has a Go CLI/MCP product and a journey docs/ corpus (dec-20260808-journey-docs-corpus-e8b5483b) but no public product motherhome. Operator wants getpysar.com on Cloudflare with a Next.js static site (latest Next, Tailwind, shadcn/ui), CI build+deploy to Cloudflare Pages, all site source under site/ so marketing/SSG stays split from tool Go code. An external verified how-to already exists for Next output:export + GitHub Actions Direct Upload to Cloudflare Pages + SEO metadata patterns; adapt that approach into this repo without naming that external project in Pysar docs. Marketing UI starts simple. Hosting/SSG choice was explicitly out of scope of the docs corpus decision — this problem is that deferred choice plus motherhome.

## Problem Type

synthesis

## Constraints

- Site source lives under site/ — split from Go tool source
- Static only: Next output export; no Node server / Cloudflare Next SSR adapter for MVP
- Cloudflare Pages hosting; domain getpysar.com DNS on Cloudflare
- Latest Next.js + Tailwind + shadcn/ui
- Honor docs corpus invariant: single docs/ tree, no divergent website-only docs copy
- Do not invent CLI/MCP/pipeline features in marketing or docs pages
- Simple UI for start — common shadcn patterns, not a design system rewrite
- CI must not break existing GoReleaser/tag-release workflow

## Optimization Targets

- Clean boundary between tool repo and motherhome package
- Deploy reliability and SEO correctness for getpysar.com

## Observation Indicators

- Number of marketing routes at MVP

## Acceptance

(1) site/ is a self-contained Next.js App Router package (own package.json) with Tailwind + shadcn, output:export producing out/. (2) GitHub Actions builds from site/ and deploys out/ to Cloudflare Pages (Direct Upload) for getpysar.com. (3) Tool Go tree (cmd/, internal/) is not polluted by Node tooling at repo root. (4) docs/ remains the single user-docs corpus — site ingests it for doc routes; no parallel website-only docs tree. (5) Baseline SEO lands: metadataBase/canonicals, sitemap.xml, robots.txt, home WebSite+Organization JSON-LD, default OG image, NEXT_PUBLIC_SITE_URL=https://getpysar.com in CI. (6) Local pnpm build + preview from site/ matches CI artifact shape.

## Blast Radius

New site/ Node package; new GitHub Actions deploy workflow; Cloudflare Pages project + DNS for getpysar.com; possible read-only ingest of docs/ at site build time; root .gitignore for site node_modules/out; README pointer to live site later
