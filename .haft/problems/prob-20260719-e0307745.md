# Voice profile templates: built-in generic default + author-saved reusable presets

## Signal

No template mechanism exists in Pysar today (confirmed by code search: only unrelated "template" hits like claudeMDTemplate and haft's own artifacts). Operator ran /ps-voice in a real test project, reviewed the resulting profile, wants to name it "Measured plain English -- speakable, understated, general audience" and ship it as Pysar's built-in "generic" voice default -- using the same underlying mechanism that will later let any author save their own completed profile as a named, reusable template across projects (operator explicitly chose this scope over a built-in-only or author-only variant).

## Problem Type

synthesis

## Constraints

- Single static binary distribution (dec-20260718-239680d4): the built-in template ships embedded in the binary, no network fetch or separate install step
- Author-saved templates must survive across projects, so they cannot live in a single project's .pysar/ -- needs a cross-project location, same class of problem already solved once for skills (dec-20260718-a2a24f32 / global ~/.claude/skills), not necessarily the same location
- Applying a template is a starting point for the /ps-voice conversation, never a silent bypass of its existing confirm-before-save step (SKILL.md Step 4) -- an author must still see and confirm the profile before it's written to .pysar/voice.md
- Must not silently overwrite an existing .pysar/voice.md the way /ps-voice already refuses to (SKILL.md Step 1 re-tune flow)
- This is the first of what the operator has already signaled will repeat for Style (pending task #11) -- the mechanism shouldn't be so voice-specific that reusing it for a second profile kind requires a rewrite, but must not be built as a speculative generic system before a second real use case exists (YAGNI vs premature reuse tension worth naming, not resolving by default)

## Acceptance

A named voice template -- starting with the shipped "generic" one -- can be offered by /ps-voice as an explicit starting point instead of a blank conversation, the author can accept-as-is or edit before saving, and the same storage/retrieval mechanism lets an author save any completed .pysar/voice.md as a new named template usable in a later project; verified with unit tests plus a real-binary smoke test per this project's standing discipline.

## Blast Radius

internal/onboarding (template type/storage), cmd/pysar (embedded built-in template asset), internal/mcpserver (likely new MCP tool(s) for listing/applying/saving templates), cmd/pysar/assets/claude/skills/ps-voice/SKILL.md (conversation flow to offer templates)
