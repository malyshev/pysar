# Voice/style template structure: schema design + built-in neutral default for zero-config use

## Signal

dec-20260718-5570376d (schema-only onboarding engine) established that a VoiceProfile/StyleProfile schema will exist, but not its actual shape. Operator wants: (1) a built-in generic/neutral default voice+style profile so an unonboarded user still gets sensible, non-Medium-personal-voice output (zero-config principle); (2) the template's field structure, including 3-4 "golden" reference examples the AI can be steered by, using the SAME schema shape onboarding itself produces -- not a divergent format. Operator explicitly scoped OUT how optional reusable templates are stored/composed/inherited beyond this generic default -- that mechanism is deferred to a separate future ADR by the operator's own instruction. Operator did real research citing external style-guide baselines (GOV.UK, Microsoft, Google dev docs, Economist/Orwell rules, Guardian/AP) and open-source voice/style schema formats (soul.md, voice.md, style.md, SKILL-TEMPLATE.md, ghostwriter, agent-writing, humanizer) as reference points -- Medium's own voice pack is explicitly a strong PERSONAL voice, not a generic one, which is exactly the gap this problem fills.

## Problem Type

synthesis

## Constraints

- Must reuse the exact schema shape as what onboarding produces (dec-20260718-5570376d) -- the generic default and an onboarded profile must be structurally interchangeable
- Template composition/inheritance mechanism is explicitly out of scope here -- deferred to a separate future ADR per operator's own instruction
- External style-guide citations and open-source schema-format references are CL1 inspiration only, never sole justification, never adopted wholesale -- the generic profile must be an original synthesis, mirroring the spirit of dec-20260718-eafefad2 even though that gate names Medium/haft specifically
- No multi-author/persona registry (dec-20260718-e84221af) -- the generic default is one neutral profile, not a set of personas to pick from
- Must fit the schema-only architecture (dec-20260718-5570376d) -- this is a data schema plus example content, not new orchestration/engine code

## Optimization Targets

- how well the schema structure supports steering AI generation via concrete examples (goldens) vs. abstract rules alone
- how well the generic default profile, once built against this schema, validates that the schema itself is sufficient

## Observation Indicators

- number of fields in the schema

## Acceptance

A voice/style template schema is defined such that: (1) a single schema shape is shared by onboarding-produced profiles and any future reusable template, including the generic default; (2) a built-in generic/neutral profile exists, populated using this schema, suitable as a zero-config fallback when no onboarding has occurred; (3) the schema includes 3-4 concrete "golden" reference examples, not abstract descriptive rules alone, that an AI can be steered by; (4) template inheritance/composition mechanics are explicitly not decided in this pass.

## Blast Radius

internal/onboarding schema package (VoiceProfile/StyleProfile struct shape), a new built-in generic default profile shipped with the binary, any future skill files that read this schema to steer generation
