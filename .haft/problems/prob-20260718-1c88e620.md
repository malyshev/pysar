# Exclude platform publish checklist from current scope -- how, and what cascades

## Signal

Operator wants the platform-scoped publish checklist (+ cover) capability excluded from Pysar's current responsibility -- judged unnecessary burden at this stage. This capability is written directly into already-approved target-system spec sections: TS.environment-change.001 names it as part of the environment-change statement and one of the four core use cases ('Go from idea to ship-ready body plus platform publish checklist'); TS.target.boundary.001 lists it explicitly in-scope ('Pysar produces the checklist, not the post'); ES.enabling.work_methods.001's actor/trigger table assigns it to the platform-adapter layer, triggered by 'I'm ready to post'. The original product pitch also promised it as an outcome. Excluding it is not a small implementation tweak -- it walks back language in specs a human already approved.

## Problem Type

optimization

## Constraints

- Must not silently leave TS.environment-change.001 or TS.target.boundary.001 inaccurate -- whatever is decided, the spec sections' actual text must be brought into agreement with it, not left contradicting the new scope
- Must not contradict dec-20260718-20a08f83's pipeline mechanism, which already assumed a 'packaging' pass exists in some form -- this decision narrows what packaging promises, it doesn't reopen how passes are dispatched
- Should reuse the already-validated staged-rollout pattern from dec-20260718-404573a2 (free/default now, explicitly deferred premium tier later) if a comparable shape fits here, rather than inventing a new deferral mechanism

## Acceptance

A scope-reduction approach is selected such that: (1) it states plainly whether already-approved TS spec sections get amended now, deferred with an explicit annotation, or left untouched with the gap absorbed elsewhere; (2) 'unnecessary responsibility' is grounded concretely -- specifically the ongoing burden of maintaining accurate, up-to-date platform-specific publishing requirements across many possible target platforms, distinct from and additional to core editorial-engine work; (3) it names what happens, concretely, when an author says 'I'm ready to post' under the new scope -- not left as an unanswered gap.

## Blast Radius

Two already-approved TargetSystemSpec sections and one EnablingSystemSpec section; the author-facing promise for 'I'm ready to post'
