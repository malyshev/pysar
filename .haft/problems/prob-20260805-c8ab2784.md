# Eliminate per-call permission prompts for ps-research/ps-factcheck/ps-intake's web grounding

## Signal

ps-research, ps-factcheck, and ps-intake's Step 4 grounding all call Claude Code's native WebFetch/WebSearch tools to fetch and search real sources. Neither tool is covered by the shipped settings.json's mcp__pysar__* wildcard (which only covers Pysar's own internal file-persistence MCP tools) or by any other permissions.allow entry -- so every single fetch/search call prompts the operator individually, observed directly in a live session (a chain of Fetch/Fetch/Fetch/WebSearch calls each requiring separate approval, WebSearch shown as interrupted mid-call). Operator asked "don't we have MCP?" (a factual misunderstanding I already corrected: mcp__pysar__* was never meant to and does not cover native web tools) then proposed, as a possible fix, building the fetch/search capability behind Pysar's own MCP server instead of pre-approving the native tools -- explicitly a proposed solution, not yet a framed problem with stated acceptance criteria.

## Problem Type

search

## Constraints

- Must not silently widen what the agent can do without the operator seeing the trade-off named explicitly (blanket web access vs. scoped/audited access)
- Must not assume a free equivalent to native WebSearch exists for a server-side reimplementation -- real web search APIs (Google Custom Search, Bing, Brave, SerpAPI) require a paid/keyed account; state this cost explicitly if a variant proposes it
- Whatever ships must work the same way for every future pysar init project, not just a one-off local settings.json edit for this session

## Optimization Targets

- Eliminate per-call prompt friction during real research/factcheck usage
- Keep the resulting trust boundary and blast radius explicit and as narrow as practical for what the feature actually needs

## Observation Indicators

- Engineering/maintenance cost of any new Go networking code -- watch, don't let it silently balloon scope beyond what removing the prompt friction actually requires

## Acceptance

A concrete approach is selected and bound via /h-decide such that: (a) ps-research/ps-factcheck/ps-intake's grounding step no longer prompts per individual fetch/search call in normal operation; (b) the resulting trust/blast-radius change is explicit and named, not a silent widening -- specifically, whether the agent gains generic, unscoped internet access (any URL, any query) or only a narrower, project-mediated capability; (c) the approach's real build/operational cost is stated honestly, including whether it requires a paid third-party search API key the operator must provision (native WebSearch has no equivalent free-and-local substitute Pysar's own Go server could call without one); (d) the decision applies to the shipped settings.json/skill pack, not just this session, since pysar init scaffolds it into every future project.

## Blast Radius

cmd/pysar/assets/claude/settings.json (ships to every pysar init project), possibly a new internal/mcpserver tool + Go HTTP client if the MCP-mediated variant is chosen, ps-research/ps-factcheck/ps-intake SKILL.md files if tool names change
