# /ps has no opt-in to make full research a mandatory pipeline stage after intake

## Signal

Shipped /ps is deliberately research-free: chain is intake → draft → staff-edit → sharpen → [--seo] → humanize → export. Research stays optional via separate /ps-research; intake/draft only do light ps-factcheck. Live dogfood showed a full /ps run can invent product capabilities and demo cases when sources stay thin (research_mode targeted, one Diátaxis URL) because nothing forces a real /ps-research pass. Operator wants an explicit opt-in flag on /ps — same surface pattern as --seo / --review — such that when the user adds --research, /ps-research MUST run as part of the pipeline after intake (before draft), not as a hope that intake/draft will ground enough on their own. Default /ps without the flag must remain research-free.

## Problem Type

synthesis

## Constraints

- Default /ps without --research must stay research-free (current contract)
- When --research is present, research is mandatory after intake — not best-effort, not skippable by agent judgment
- Reuse existing /ps-research skill via Skill tool; do not fork a second research implementation inside /ps
- Flag surface matches existing /ps opt-ins (--seo, --review): operator text flag parsed by skill prose, not a new Cobra CLI binary flag unless explore proves otherwise
- Must not silently reorder or break --seo-before-humanize (dec-20260804-e3234e50)
- Transformer Mandate: variants via explore; binding via manual /h-decide

## Optimization Targets

- Operator can force a source-backed pass in one /ps invocation without a separate /ps-research babysit step
- Clear MUST semantics so an executing agent cannot treat research as optional once the flag is set

## Observation Indicators

- Whether --research alone reduces product-capability hallucination without a separate product-grounding gate
- Latency / permission-prompt cost of always running web research when flagged (related to parked prob-20260805-c8ab2784)

## Acceptance

With /ps --research <idea|@piece>, after intake has a piece (brief.md), the orchestrator invokes ps-research on that piece and save_research_bundle succeeds (research_mode full / non-empty sources.md as that skill defines) before any later stage that consumes the piece for drafting runs; without --research, /ps never invokes ps-research. Resume behavior is defined: a piece that already has full research does not re-run research unless force semantics are decided. Documented in ps/SKILL.md argument-hint and docs/pipeline.md. Verifiable by reading skill chain + a dogfood run-log showing intake then research then draft when the flag is present.
