# Cursor IDE authors cannot run Pysar's agentic editorial pipeline

## Signal

Operator wants Pysar usable inside Cursor IDE as the next AI-editor host after Claude Code. Today: pysar init --cursor is intentionally stubbed (dec-20260718-8278c494) with 'not yet supported'; all ps-* skill bodies, permission pre-approvals, and MCP launch config ship only under assets/claude/ into ~/.claude/skills + project .claude/settings.json + .mcp.json. A Cursor author who installs the pysar binary still has no host-native way to invoke the pipeline (equivalent of /ps, /ps-intake, …) or to get pysar serve wired with the same mechanical-I/O contract. Prior problem prob-20260718-35d97dc6 only covered flag/dispatch shape, not real Cursor scaffold content. 'Support Cursor' is the proposed solution label — the broken condition is missing Cursor-host scaffolding for the already-shipped agentic surface.

## Problem Type

synthesis

## Constraints

- Preserve dec-20260718-8278c494 flag surface (--cursor stays a boolean; mutual exclusivity with --claude/--codex)
- Do not weaken host-agnostic skill content invariants (skills must not become Claude-only prose; Cursor packaging may differ, editorial rules must not)
- Piece I/O remains via pysar MCP (dec-20260719-fa0366dd class of decision) — no regression to agent Write/Bash for .pysar/**
- Implementing a second real host is the recorded trigger to migrate to V3 hostAdapter+registry from sol-20260718-9dc51a75 / dec-20260718-8278c494 consequences — do not invent a third dispatch shape without revisiting that decision
- Codex remains out of scope for this problem unless it falls out of a shared adapter with zero extra product commitment
- No external-POC/haft copy-paste of host conventions beyond CL1 inspiration

## Optimization Targets

- Time-to-first-piece for a Cursor author who already has pysar on PATH
- Reuse of existing skill bodies (minimize divergent Cursor-only editorial logic)

## Observation Indicators

- How often Cursor's permission/MCP UX still forces extra operator clicks despite scaffold (measure; do not optimize scaffold complexity around eliminating every click)

## Acceptance

From a clean scratch directory, `pysar init --cursor` exits 0 and writes a Cursor-host project such that: (1) Cursor can launch `pysar serve` as an MCP server for that project without hand-editing config; (2) the operator can invoke an agentic entry equivalent to the Claude /ps orchestrator (and at least the stage skills /ps-intake through /ps-humanize + onboarding) with instructions that match the host-agnostic skill bodies already shipped; (3) piece persistence still goes through pysar MCP tools (not raw Write/Bash for .pysar/**); (4) `pysar init --claude` behavior is unchanged; (5) a short smoke: open the project in Cursor, run the entry command with a one-sentence idea, and observe a provisional piece directory under .pysar/pieces/ with brief.md written via MCP.

## Blast Radius

cmd/pysar init path (scaffoldCursor + possibly host adapter registry), new assets under cmd/pysar/assets/cursor/ (or shared assets/), README quick-start, possibly AGENTS.md/.cursor project files; amends/extends dec-20260718-8278c494 from stub to real Cursor host; does not change editorial Pass semantics or piece file formats
