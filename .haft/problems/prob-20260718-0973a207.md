# Delivery model for the semantic memory engine (V2): local-standalone vs. cloud-dependent vs. hosted SaaS feature

## Signal

V2 (embedding-based semantic similarity) was the leading technique for catching paraphrased repetition, but 'embeddings' implies either a local ML model or a network call somewhere -- neither is free, and the target user for this question is explicitly non-technical (operator's proxy: 'even a homewife writing kitchen stories'), not someone comfortable managing API keys or config files. Operator is asking whether V2 can be fully standalone and easy to install for such a user, what concrete resources it needs, and whether 'memory' should instead be delivered as a premium hosted (SaaS) feature rather than bundled into the local binary.

## Problem Type

synthesis

## Constraints

- Must not silently violate dec-20260718-239680d4's invariant that the distributed Pysar binary remains a single self-contained executable requiring no separate runtime install -- a variant may accept that trade-off, but must say so explicitly
- Per ES.enabling.effect_boundaries.001, only the platform-adapter/imperative-shell layer may touch network -- any network-dependent variant must fit that existing boundary, not invent a new one
- If a SaaS/hosted option is considered, that is a business-model decision (ongoing hosting cost, pricing, support), not purely a technical one -- must be flagged as such, not decided as if it were only an engineering choice

## Acceptance

A delivery-model variant is selected such that, per variant: (1) it's stated plainly whether end-user setup requires anything beyond running the single Pysar installer/binary -- no manual API key entry, no account signup, no separate dependency install -- a concrete yes/no, not a vague 'easy'; (2) real resource costs are named (approximate binary size delta, disk, RAM, network requirement); (3) it's explicit whether the variant preserves or breaks the 'single self-contained executable, no separate runtime' invariant already recorded in dec-20260718-239680d4, and if it breaks it, that conflict is surfaced, not hidden.

## Blast Radius

Delivery/business model of the memory engine specifically -- but a SaaS component would be the first network-dependent, potentially-paid surface in Pysar, which is a meaningful precedent for the whole product's shape, not just this one feature
