# Global skill artifact refresh mechanism: automatic vs. manual (--force)

## Signal

pysar init --force (just implemented, evidence attached to dec-20260718-fe926229) requires the operator to know about and explicitly type a flag to refresh a stale global skill -- this already caused real, repeated confusion (four separate incidents in one session) before the flag existed to fix it. Operator observes these global files (~/.claude/skills/ps-*) are system-owned and never hand-edited by the author, and proposes purging/recreating them automatically on reinstall so updates land with zero manual step. Operator explicitly requests exploring the full option space, not adopting this one proposal directly.

## Problem Type

synthesis

## Constraints

- Scope is strictly the global ~/.claude/skills/ps-* tree, which the operator has now explicitly classified as system-owned -- must not extend this same mechanism to project-local files (CLAUDE.md, .pysar/**, project .claude/settings.json, .mcp.json), which stay governed by the existing never-clobber-without-force behavior
- Must not silently destroy a genuine future customization if one ever exists, even if today's real-world risk is near-zero -- name the risk explicitly rather than assume it away
- Must work within the single static binary distribution model (dec-20260718-239680d4) -- no separate updater process or daemon
- Should not require the operator to remember a flag for the common, correct outcome of always running the current shipped version

## Optimization Targets

- how reliably an operator ends up running the current shipped skill content without manual intervention
- how much unnecessary I/O/churn happens on every init when nothing has actually changed

## Observation Indicators

- new state/marker files introduced
- risk surface for destroying a hypothetical real customization

## Acceptance

A mechanism is selected such that: (1) after a pysar binary upgrade, the very next pysar init (no special flag required) leaves the operator running the current shipped skill content; (2) nothing is rewritten when installed content already matches the current shipped version -- repeated init with no upgrade in between causes zero unnecessary writes; (3) the mechanism's risk to a genuine future customization is explicitly named, not silently ignored.

## Blast Radius

cmd/pysar/main.go's global-skill-install path, ~/.claude/skills/ps-*, the just-added --force flag (may be superseded, extended, or kept as a manual escape hatch depending on outcome)
