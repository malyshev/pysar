# Pysar command-interface naming convention: CLI subcommand prefix and slash-command entry point

## Signal

Pysar needs a consistent naming convention for its command surface before any commands are defined: a CLI subcommand prefix (analogous to haft's own commands) and a slash-command entry point for auto/agent mode. Operator proposes `ps-*` for individual commands and `/ps` for auto mode, motivated by brevity and wordplay (ps = Pysar initials, and 'post scriptum' / 'pssst... I have an idea'). No command list is being decided here -- only the naming/prefix convention.

## Problem Type

synthesis

## Constraints

- Must not enumerate or lock the actual command list -- operator explicitly deferred that
- Per dec-20260718-eafefad2 (reference-agnosticism gate): if compared against haft's own '/h-*' convention, that comparison is inspiration-grounding only (CL1 at most), never justification on its own, and must state what's Pysar-original

## Acceptance

A prefix convention is recorded such that: (1) it is short enough for comfortable typing in a global CLI context; (2) it does not silently collide with a near-universal existing shell command in a way that risks user confusion or aliasing conflicts; (3) it carries an intentional, stated meaning (not arbitrary letters); (4) it is documented as a convention future command names must follow, without yet enumerating the command list itself.

## Blast Radius

The entire future command/skill surface of Pysar -- every command name that gets defined later inherits this prefix convention
