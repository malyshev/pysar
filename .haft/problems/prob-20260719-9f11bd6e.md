# Template identity: persisted display name decoupled from a stable machine slug

## Signal

Live testing of dec-20260719-3e36577e surfaced a real gap: save_voice_template currently derives the on-disk filename slug directly from the author's display name (onboarding.Slug(name)), so a rename would silently change the template's addressable key too -- name and slug are one conflated thing, not two. The built-in generic template makes this concrete: its only name-bearing data is the bare filename stem "generic" -- the meaningful display name the operator actually chose for it ("Measured plain English -- speakable, understated, general audience") was only ever used as descriptive prose during design, never persisted as data, so list_voice_templates has nothing but "generic" to show. Operator wants both a persisted, meaningful display name AND a separate stable slug/key that survives renames, explicitly for future automation (addressing a specific template by a fixed key regardless of what it's currently called).

## Problem Type

synthesis

## Constraints

- Must not silently break the existing schema-parity constraint from prob-20260718-00bf7ca6 (templates and onboarding profiles share one Profile schema) -- if Profile itself gains a name-like field, that must be an explicit, examined divergence, not an accident
- Slug stability must survive a rename: re-saving a template under a new display name but the same slug updates the existing file in place, never creates an orphaned duplicate
- The author must never be asked to type or think about a slug during the /ps-voice conversation -- slugs are machine-facing, names are human-facing
- Must stay inside the already-decided global template store location and never touch project-local files (dec-20260719-3e36577e invariant)
- Must reuse the existing hash-refresh/manifest mechanism (dec-20260719-25712417 via dec-20260719-3e36577e) rather than a second parallel implementation

## Acceptance

A template carries a persisted display name distinct from its stable slug. Renaming a template's display name (re-saving under a new name) never changes its slug or creates an orphaned duplicate file. list_voice_templates surfaces both the stable slug and the current display name. The built-in generic template's slug is "generic" and its display name ("Measured plain English -- speakable, understated, general audience") is actually persisted as data, not only prose. Verified with unit tests plus a real-binary smoke test per this project's standing discipline.

## Blast Radius
