# Operator-facing copy still names external brands/platforms where Pysar should stay agnostic

## Signal

Operator reacted to an audit label that surfaced 'prior writing POC' in the voice/onboarding story ('Голос автора без hardcoded platform-шаблонів'). prior writing POC is the operator's own writing POC (CL1 inspiration under dec-20260718-eafefad2), not a product dependency — but it and other brand/platform names still appear in skills, docs, site, and governance prose. Operator wants options to remove, anonymize, or agnosticize references to brands/known platforms so audits and authors do not read Pysar as brand-coupled or otherwise brand-locked. Scope must distinguish (a) historical/internal governance citations, (b) necessary host product names for init/install (Cursor/Claude/Codex), (c) third-party integration brands (newsletter host, analytics), (d) skill admonitions that say 'no platform-specific X'.

## Problem Type

synthesis

## Constraints

- Must not break init --cursor/--claude/--codex discoverability — host product names remain where they name a real spawn/config path
- Must not violate dec-20260718-eafefad2 by inventing false history; anonymization of past DRRs must not erase CL1 discipline
- Transformer Mandate: policy bind requires explicit /h-decide
- Do not rewrite unrelated marketing partners (United24 etc.) unless operator expands scope
- Stay-on-topic: no drive-by site redesign

## Optimization Targets

- Author/auditor-facing surfaces free of prior-POC brand coupling
- Clear allowlist for unavoidable host/integration names

## Observation Indicators

- Number of remaining prior writing POC hits in .haft after policy
- Reader confusion about supported hosts if names are over-scrubbed

## Acceptance

A selected policy (via later /h-decide) defines which surfaces must be brand-free vs may name hosts/integrations, with a concrete rewrite checklist and a grep/audit fixture: no prior writing POC (or equivalent prior-POC) name in author-facing skills/docs/site copy; remaining host names only where they are the install target; governance may keep CL1-named history behind a documented anonymization rule or leave as-is. Acceptance is met when an auditor scanning skills+docs+site for the prior-POC brand finds zero hits, OR finds only an explicitly allowlisted exception list recorded in the decision.

## Blast Radius

cmd/pysar/assets/skills/**, plugins/pysar/skills/**, docs/**, site copy that mentions prior writing POC/prior POC; optionally .haft historical prose; README
