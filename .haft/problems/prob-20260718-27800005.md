# Bare `pysar` invocation needs a meaningful product intro, not hello-world

## Signal

Running `pysar` with no args currently prints `pysar: hello world` (cmd/pysar/main.go). That was enough to prove the build/install loop (dec-20260718-817bfb74) but is not a usable product surface: a newly installed or returning user gets no statement of what Pysar is, what surfaces it has (console CLI vs agentic /ps), what to try next (e.g. init), or how to get help/version. Operator wants a meaningful intro comparable in job-to-be-done to the dogfood CLI's bare-invoke output (purpose blurb + surfaces + examples + usage) — haft is inspiration only (CL1 max per dec-20260718-eafefad2), not a template to copy. Subcommands already exist (init, --version) but are undiscoverable from the default path.

## Problem Type

synthesis

## Constraints

- Must not copy-paste haft's blurb or command list; any dogfood citation is CL1 inspiration with explicit Pysar-original divergence (dec-20260718-eafefad2)
- Console binary remains `pysar`; agentic `ps-*`/`/ps` naming (dec-20260718-a2a24f32) must not be conflated as if bare `pysar` were the slash-command surface
- Must not invent or imply subcommands that do not exist yet — only document real commands (today: init, --version) plus honest pointers for deferred surfaces
- Plain Go toolchain only (dec-20260718-817bfb74) — no new CLI framework required by this problem unless a variant explicitly accepts that cost
- Intro text must respect author-surface/harness-surface term map: no intake/staff-edit/sharpen/SEO vocabulary forced onto users

## Optimization Targets

- cold-start discoverability of real commands
- accurate product identity in one screen

## Observation Indicators

- word-count of the intro (watch for bloat, do not optimize for maximum length)

## Acceptance

Invoking `pysar` with no arguments (and ideally `pysar --help` / `pysar help` if chosen) prints a short, accurate product intro that: (1) states what Pysar is in author-facing or clear console language without leaking internal phase names; (2) names at least the console entry actions that exist today (e.g. init, --version) with one-line purpose each; (3) gives at least one copy-pastable example; (4) exits 0 (or a documented help exit code) without side effects. Observable: `pysar` output no longer contains `hello world` and a cold reader can answer 'what is this and what do I run next?' from stdout alone.

## Blast Radius

cmd/pysar default path and help/version UX; first impression for every install; sets pattern for future subcommand discovery text
