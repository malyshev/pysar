# Post-install agent briefing: what Pysar is + voice/style onboarding

## Signal

URL-drop + 'install' path (dec-20260808-homepage-ai-install-signals-9eb5a6a9) currently instructs host agents to curl install.sh and pysar init — mechanical setup only. After init, the author may still not hear what Pysar is, why it helps writers, how to use it, or that /ps-onboard captures their own voice and style instead of a generic default. Existing /ps Step 0 can mention /ps-onboard when voice/style are missing, but that fires only when the author already starts the pipeline — not at the install moment. Operator asks whether we can make the AI editor tell the user about the product and especially onboarding after install. Honest constraint: hosts cannot be forced; we can only publish instructions the agent is likely to follow. Related: note-20260809-71c53352 (hero overloaded with install framing for humans) and note-20260808-26ff4eb4 (/llms.txt complement).

## Problem Type

synthesis

## Constraints

- Cannot literally force host agents — only instruct via published carriers + installed skills
- Must not break static Next export + Pages (dec-20260808-da785647)
- Must not contradict journey docs install/init or invent competing install paths
- Human marketing first viewport must not become AI/onboarding wall of text (promo note: hero already overloaded)
- Respect Pysar output discipline (dec-20260719-7d675b61) — briefing must be actionable, not noise; skip narration when onboarding already complete
- Voice/style onboarding stays conversational via ps-voice/ps-style/ps-onboard — do not replace with a static questionnaire dump in the install carrier
- Host coverage: Claude Code, Cursor, Codex

## Optimization Targets

- Fraction of install smokes where briefing+onboarding CTA appears
- Author understanding that defaults are generic until their voice/style are captured

## Observation Indicators

- Briefing length / message count (watch for spam)
- Human homepage first-viewport clutter if carrier grows
- Agent truncating long homepage HTML and missing the briefing step

## Acceptance

In a live smoke on at least 2 of 3 supported hosts (Claude Code, Cursor, Codex): after URL-drop + 'install' completes binary-on-PATH + host init, the agent's next user-visible message (before or instead of inventing next steps) includes (1) a short plain-language what/why of Pysar for writers, (2) the next recommended action naming /ps-onboard (or equivalent) to capture the author's own voice and style rather than leaving the project on generic defaults, and (3) does not contradict docs/install or invent brew/npm/go-get. Observable in the chat transcript; silent skip of the briefing fails.

## Blast Radius

Homepage AI install carrier, /llms.txt, possibly shared skill corpus post-init instructions, init messaging; no Go editorial engine change required for first cut
