# Piece/export slugs collapse non-Latin titles to template-{hash}

## Signal

Operator wrote a Ukrainian-language piece; on-disk piece dir / export file resolved to template-<hex> instead of a readable Latin slug of the title/idea. Verified cause: onboarding.Slug (internal/onboarding/profile.go) only keeps ASCII [a-z0-9] and returns the literal fallback "template" when the input has no Latin letters — Cyrillic/other scripts are stripped entirely. intake.AllocateUniqueName then suffixes that fallback → template-{12-hex}. Export uses the piece directory basename as <slug>.md at project root. Same ASCII-only class of failure as intake.Degenerate before dec-20260809-degenerate-unicode-i18n-5008f0e6, now on the naming/export path. Operator wants a solid transcription/transliteration mechanism so any-language titles yield stable Latin-letter slugs.

## Problem Type

synthesis

## Constraints

- No third-party network call at slug time (offline, deterministic)
- Slug remains machine-facing; authors are never asked to invent a Latin slug in conversation
- Must not break rename-stable template slug contract from dec-20260719-b12539fa for already-shipped ASCII template keys (e.g. generic)
- Filesystem-safe on macOS/Linux/Windows common cases (no spaces, no path separators)

## Optimization Targets

- Readable Latin prefix from non-Latin titles for piece dirs and export filenames
- Determinism: same input → same slug prefix across runs/machines

## Observation Indicators

- Whether linguists agree on a specific national transliteration standard (watch; do not block shipping a reversible default)
- Whether SEO/public URL slug is the same carrier as piece dir name (watch; may diverge later)

## Acceptance

DRAFT: Given a Ukrainian title (and at least one other non-Latin script fixture, e.g. Japanese or Arabic), AllocateUniqueName / export produce a piece dir and root export filename whose readable prefix is non-empty Latin [a-z0-9-] derived from the title (not the bare fallback "template"), remains filesystem-safe, and unit tests lock Cyrillic→Latin mapping for a fixed fixture. Existing English/ASCII slug behavior for Latin-only names stays unchanged.

## Blast Radius

internal/onboarding.Slug (shared by templates + intake piece naming + export basename); tests in onboarding/intake/export; possibly new small transliteration helper package
