# Tag push publishes even when no product-worthy change warrants a release

## Signal

Observed 2026-08-08: force-pushing rewritten tag v0.1.0 (author email chore only — no product code change) re-triggered .github/workflows/release.yml; GoReleaser failed with GitHub 422 already_exists on every release asset (release-id 366204459). Current pipeline treats every tags:v* push as a full publish. Existing decision dec-20260805-db745b4a requires an explicit tag push as the deliberate publish action, but has no second gate for whether that push represents a product-worthy change (feat/fix) vs history/metadata chore, and no idempotency when the GitHub Release for that tag already has assets.

## Problem Type

optimization

## Constraints

- Preserve dec-20260805-db745b4a invariant: no scheduled/automatic releases without an explicit deliberate operator action (tag push or equally explicit equivalent)
- Must not remove the CI test job gate before build/publish (needs: [test])
- Default GITHUB_TOKEN remains sufficient — no new PATs/secrets unless a later decision requires them
- Single-maintainer scale: no heavy release-it/semantic-release Node toolchain unless it clearly earns its keep vs a small workflow gate

## Optimization Targets

- Zero false-publish / false-fail on chore-only or retag events
- Keep intentional feat/fix releases as one deliberate operator action

## Observation Indicators

- How often operators want a forced republish of the same tag (measure; do not optimize the gate around rare force-republish)

## Acceptance

A tag push that does not introduce any conventional-commit feat|feature|fix since the previous version tag exits the release workflow green without creating or mutating GitHub Release assets; a tag push that does include at least one such commit still publishes a complete cross-platform release as today; re-push of an already-published tag does not fail CI with 422 already_exists.

## Blast Radius

.github/workflows/release.yml and possibly .goreleaser.yaml; amends or supersedes aspects of dec-20260805-db745b4a release-trigger semantics; no change to pysar product code or install.sh consumer contract if skip path is silent-success

## Reversibility

high
