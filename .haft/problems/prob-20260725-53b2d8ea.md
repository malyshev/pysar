# /ps-intake: scaffold brief/outline/angles from an operator idea or draft

## Signal

Pysar has no way for an author to start a piece today -- no idea-intake command exists. Operator wants /ps-intake: given an idea (one sentence/paragraph) or --from-draft=&lt;path&gt; (existing notes/partial prose), the agent forces itself into a correct expert framing of the topic, then scaffolds a brief, outline, and angles the way a human editor would before writing starts. Operator supplied a real, previously-shipped reference: that prior POC's POC ([prior-writing-POC]/.cursor/commands/w-intake.md + .cursor/skills/article-intake/SKILL.md), explicitly as unproven prior art to mine, not to port wholesale -- operator already named two things in it that must NOT carry over: (1) an author registry/--author flag (prior writing POC supports multiple authors; Pysar does not), (2) a fixed --length=N cap on the brief (brief length should follow from the idea/problem's actual shape, not an operator-supplied word-count ceiling that could truncate a topic that genuinely needs more room).

This is not a green-field command. Pysar already has two relevant architectural decisions this must compose with, not bypass: dec-20260718-20a08f83 decided the orchestration mechanism every author-facing pass must plug into (piece state = a set of produced-ArtifactKind refs, each pass owns its own Precondition check, no central phase enum) and dec-20260718-6ba897d4 decided every pass that runs appends a structured entry to the piece's run-log. /ps-intake would be the FIRST real author-facing pass to actually implement this mechanism end-to-end (dec-20260718-20a08f83's own 2026-07-19 measurement already flags 'CLI/skill entrypoints not yet routing through editorial.Run' as still-open). Separately, and left genuinely unresolved: prob-20260718-f6ac8127 (on-disk piece/project structure, storage location, schema evolution) is still an ACTIVE, undecided ProblemCard with an existing SolutionPortfolio (sol-20260718-fcc29be3) but no bound decision -- meaning WHERE brief.md/outline.md/angles.md-equivalent artifacts physically live on disk, and what the base file set is, has no answer yet. /ps-intake's content contract (what an idea/draft becomes) and its storage topology (where that becomes a file) are two different open questions; this ProblemCard scopes to the former and treats the latter as a named adjacent dependency, not something to silently assume.

## Problem Type

## Constraints

- Must plug into dec-20260718-20a08f83's precondition-guarded pass mechanism as its own pass with its own Precondition check (produced-artifact state as ArtifactKind refs, no separate ad hoc flow) and append to dec-20260718-6ba897d4's run-log on a successful run -- this is the first pass to actually route through editorial.Run per that decision's own open measurement item
- No author registry, --author flag, or per-author resolution of any kind -- prob-20260718-97b5a2a3 already excludes the multi-author model from Pysar's target-system scope entirely; this is precedent to cite, not a fresh call
- No fixed/operator-supplied word-count cap on the brief (diverges from the POC's --length=N) -- brief depth/length must be a function of the idea's actual complexity, decided by the agent's expert-mode judgment during scaffolding, not truncated or padded to hit an externally supplied number
- Storage location/topology for the produced artifacts (brief/outline/angles-equivalent) is governed by prob-20260718-f6ac8127, which is still ACTIVE and UNDECIDED -- this ProblemCard must not silently assume a file layout; it scopes to WHAT intake produces (content contract, expert-mode behavior, required sections) and treats WHERE it's written as an explicit open dependency for exploration to address (e.g. provisional layout vs. blocked-until-decided vs. in-memory-only first pass)
- a prior writing POC is real, operated prior art -- CL1-capped inspiration only per dec-20260718-eafefad2's reference-agnosticism gate, never sole justification; every divergence from it (no authors, no length cap, and whatever else exploration surfaces) must be named as a deliberate Pysar-original choice, not an oversight
- Must fit the MCP-mediated write pattern already established for author-facing content (dec-20260719-3e36577e / dec-20260725-3a0e3022: a skill drives the conversation, an MCP tool validates and persists server-side) rather than the skill doing raw file writes directly
- No web search / synthesized research at intake time -- the POC's own INTAKE-phase rule ('no web search, preserves author POV') is a legitimate constraint to inherit since it matches Pysar's already-stated author-practitioner-voice priorities, not something to silently drop just because it wasn't operator-restated

## Acceptance

A ProblemCard + SolutionPortfolio exist such that the operator can /h-compare and /h-decide among concrete variants for: (A) what expert-mode behavior means here -- how the agent forces correct understanding of the idea before scaffolding (e.g. clarifying questions, restating the stake, topic-family/expert-persona selection) and how draft-extraction differs from idea-only entry; (B) what artifacts intake produces and their required shape (brief content sections, outline granularity, angles requirements such as a mandatory contrarian take) adapted from the POC's brief-assembly contract with authors and length-cap removed and no unnamed platform leftovers left in; (C) how intake's own Precondition check and run-log entry are defined, satisfying dec-20260718-20a08f83's and dec-20260718-6ba897d4's invariants; (D) an explicit, named position on the storage-topology dependency (prob-20260718-f6ac8127) -- not a silent default. Each variant states its weakest_link.

## Deprecated (2026-07-25)

**Reason:** Acceptance criteria (A) treated 'how the agent forces correct understanding' as an open design question with multiple viable answers, including an explicit-confirmation-gate variant. Discussion with operator resolved this: audience/register/depth defaults are never intake's own judgment call -- they're read from the author's already-established voice/style profile (a children's-book author and a cybersecurity practitioner get materially different defaults for the identical input 'write something about AI', with zero questions asked). A blocking clarification question is reserved for genuinely degenerate input only, not vague-but-resolvable input. Superseded by a re-framed ProblemCard with this as a stated invariant rather than an open axis.
