# Isolated site/ package + GHA Direct Upload (recommended shape)

## 1. Problem Frame

**Signal:** Pysar has a Go CLI/MCP product and a journey docs/ corpus (dec-20260808-journey-docs-corpus-e8b5483b) but no public product motherhome. Operator wants getpysar.com on Cloudflare with a Next.js static site (latest Next, Tailwind, shadcn/ui), CI build+deploy to Cloudflare Pages, all site source under site/ so marketing/SSG stays split from tool Go code. An external verified how-to already exists for Next output:export + GitHub Actions Direct Upload to Cloudflare Pages + SEO metadata patterns; adapt that approach into this repo without naming that external project in Pysar docs. Marketing UI starts simple. Hosting/SSG choice was explicitly out of scope of the docs corpus decision — this problem is that deferred choice plus motherhome.

**Constraints:**
- Site source lives under site/ — split from Go tool source
- Static only: Next output export; no Node server / Cloudflare Next SSR adapter for MVP
- Cloudflare Pages hosting; domain getpysar.com DNS on Cloudflare
- Latest Next.js + Tailwind + shadcn/ui
- Honor docs corpus invariant: single docs/ tree, no divergent website-only docs copy
- Do not invent CLI/MCP/pipeline features in marketing or docs pages
- Simple UI for start — common shadcn patterns, not a design system rewrite
- CI must not break existing GoReleaser/tag-release workflow

**Acceptance:** (1) site/ is a self-contained Next.js App Router package (own package.json) with Tailwind + shadcn, output:export producing out/. (2) GitHub Actions builds from site/ and deploys out/ to Cloudflare Pages (Direct Upload) for getpysar.com. (3) Tool Go tree (cmd/, internal/) is not polluted by Node tooling at repo root. (4) docs/ remains the single user-docs corpus — site ingests it for doc routes; no parallel website-only docs tree. (5) Baseline SEO lands: metadataBase/canonicals, sitemap.xml, robots.txt, home WebSite+Organization JSON-LD, default OG image, NEXT_PUBLIC_SITE_URL=https://getpysar.com in CI. (6) Local pnpm build + preview from site/ matches CI artifact shape.

## 2. Decision

**Selected:** Isolated site/ package + GHA Direct Upload (recommended shape)

**Selection policy:** Prefer the variant that (1) keeps Node package ownership entirely under site/ with no root package.json, (2) uses static Next output:export + GitHub Actions Direct Upload to Cloudflare Pages (verified pattern), (3) ingests repo-root docs/ at build time so dec-20260808-journey-docs-corpus single-corpus invariant holds, (4) leaves GoReleaser untouched. Reject root JS workspace noise, CF Git-builder split-brain, marketing-only docs skip, and SSR adapters for MVP.

**Why selected:** V1 matches the operator constraints and acceptance literally: site/ owns the Next/Tailwind/shadcn package; CI builds and uploads out/ to Pages for getpysar.com; docs stay one corpus via ingest; SEO spine and NEXT_PUBLIC_SITE_URL=https://getpysar.com land in the same package. It reuses a already-verified static Direct Upload pipeline without relocating Node authority to the repo root or introducing SSR.


**Invariants:**
- site/ is the only Node package root for the motherhome (no root package.json for this product surface)
- Production runtime is static export only — no Cloudflare Next SSR / OpenNext adapter for MVP
- docs/ remains the single user-docs corpus; site ingests it and must not grow a divergent website-only docs tree
- Deploy uses GitHub Actions Direct Upload of site/out to Cloudflare Pages with CLOUDFLARE_* secrets
- CI production builds set NEXT_PUBLIC_SITE_URL=https://getpysar.com (never *.pages.dev)
- Existing GoReleaser / tag-release workflow stays independent of site deploy
- Marketing and docs copy describe shipped behavior only

**Pre-conditions:**
- [ ] ProblemCard prob-20260808-72fab46c and portfolio sol-20260808-8aa0e850 remain the governing frame
- [ ] Operator will complete Cloudflare domain/Pages/secrets setup (site/docs/human-setup.md) before first production deploy

**Post-conditions:**
- [ ] site/ Next App Router package with Tailwind + shadcn and output:export builds to site/out
- [ ] .github/workflows/deploy-getpysar.yml (or equivalent) path-filters site/** and docs/** and deploys via wrangler pages deploy
- [ ] getpysar.com serves motherhome with baseline SEO artifacts (sitemap, robots, canonicals, home JSON-LD)
- [ ] docs journey pages available under /docs from ingested docs/

**Admissibility:**
- NOT: NOT: Root pnpm workspace / root package.json for the motherhome
- NOT: NOT: Cloudflare Next SSR or OpenNext for MVP
- NOT: NOT: Parallel website-only docs tree that diverges from docs/
- NOT: NOT: Coupling site deploy to v* GoReleaser tags

## 3. Rationale

**Counterargument:** V4 (marketing-only) ships a live getpysar.com faster with zero docs-path coupling; investing in ingest now couples every docs edit to the site CI and delays the first public URL for a dual-use benefit that GitHub already provides today.

**Selected variant weakest link:** docs/ lives outside site/; a wrong relative ingest path or a path filter that omits docs/** yields empty/stale /docs routes while the motherhome still deploys green.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| Isolated site/ package + GHA Direct Upload (recommended shape) | **Selected** | V1 matches the operator constraints and acceptance litera... |
| Root pnpm workspace wrapping site/ | Rejected | Puts package.json/lockfile at repo root next to go.mod and blurs the Go-vs-site split the acceptance criterion requires. |
| Cloudflare Git-integrated Pages build (no GHA upload) | Rejected | Moves build authority off GitHub Actions, losing the verified lint/test/verify-out/ gate and Node/pnpm pin control used in the Direct Upload how-to. |
| Marketing-only site/; docs stay GitHub-only | Rejected | Skips docs ingest and weakens the dual-use intent of the active docs corpus decision; thinner SEO topical surface on the apex domain. |
| OpenNext / Workers SSR adapter on Cloudflare | Rejected | Contradicts static-only MVP; adds adapter lock-in with no required server feature. |

**Evidence requirements:**
- CI green deploy of site/out to Cloudflare Pages project for getpysar
- View-source or out/ check: one home H1, canonical apex, OG tags, WebSite+Organization JSON-LD
- Cold check that docs pages render from ingested docs/ frontmatter

**Predictions:**
| Claim | Observable | Threshold |
|-------|------------|-----------|
| pnpm build inside site/ produces out/index.html, out/sitemap.xml, and out/robots.txt with NEXT_PUBLIC_SITE_URL baked to https://getpysar.com in CI | CI verify step and/or local pnpm build artifact listing under site/out | All three files present; sitemap loc URLs use https://getpysar.com host |
| Docs ingest exposes at least the journey index and the six aspect pages under /docs without copying prose into site/ | Built HTML under site/out/docs/ (or equivalent) corresponding to docs/*.md; no duplicate docs corpus under site/content | index + install, init, pipeline, mcp-and-skills, export, troubleshooting routes present after build |
| Go tool tree remains free of root Node package authority after scaffold | Absence of repo-root package.json/pnpm-lock.yaml; go.mod remains sole root language manifest for the tool | No root package.json committed for motherhome |

## 4. Consequences

**Rollback plan:**
Triggers:
- site/ CI repeatedly fails or blocks unrelated Go work
- docs ingest path produces wrong/empty public docs while GitHub docs remain correct
- Static export constraints block a required motherhome feature that only SSR can satisfy
Steps:
1. Disable or delete deploy-getpysar workflow
2. Remove or archive site/ package (keep site/docs approach notes if useful)
3. Revert root .gitignore site entries if unused
4. Roll back Cloudflare Pages deployment or remove custom domain binding if abandoning host
Blast radius: Public getpysar.com availability; site/ Node tree; one Actions workflow; Cloudflare Pages project — Go CLI/MCP and docs/ prose remain intact

**Refresh triggers:**
- Need for server-side dynamic routes or auth on getpysar.com
- Addition of a second Node package that forces a workspace
- Cloudflare deprecates Direct Upload / Pages static hosting path we rely on
- Docs ingest coupling causes repeated broken deploys

**Affected files:** site/, site/README.md, site/docs/approach.md, site/docs/deploy-pipeline.md, site/docs/human-setup.md, .gitignore, .github/workflows/deploy-getpysar.yml, docs/, README.md
