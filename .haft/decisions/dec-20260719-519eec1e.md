# Single combined show-and-confirm step

## 1. Problem Frame

**Signal:** Current /ps-voice and /ps-style Step 1a behavior, once a template is selected, still walks through every field conversationally ("still actually have the conversation -- confirm each field feels right for them... Treat the template as a first draft you're editing together, not a form to auto-submit"). Operator finds this unwanted friction: they want template selection to be a fast, low-friction apply -- not a full re-interview -- with fine-tuning available only later, by re-running the skill on an already-set-up profile (the existing Step 1 re-tune flow). Requested symmetrically for both /ps-voice and /ps-style.

**Constraints:**
- Must never silently adopt/save a template without the author seeing what will be saved and having a chance to change it -- an explicit What-NOT-to-do invariant already established in both skills
- Must apply identically to /ps-voice and /ps-style -- operator explicitly requested symmetric behavior
- Must not remove or weaken the existing Step 1 re-tune flow for already-saved profiles -- not in scope
- Reversible, bounded blast radius -- prompt-only change to two already-shipped SKILL.md files, no schema or tool changes

**Acceptance:** Selecting a template in Step 1a leads to a fast confirm-or-edit step (not a field-by-field walkthrough) before saving; an author who wants to adjust specific fields can do so in that single step, but is never marched through each field individually; fine-tuning an already-saved profile continues to work exactly as today via Step 1's re-tune path. Applied identically in /ps-voice and /ps-style.

## 2. Decision

**Selected:** Single combined show-and-confirm step

**Selection policy:** Constraint-gated selection (never_silently_saves, symmetry_voice_style must hold); friction_when_applying_template is the target the operator explicitly asked to minimize, measured as prompt count. Declared before scoring (sol-20260719-4d49e88a).

**Why selected:** V1 is the only variant satisfying the safety constraint (never silently save) while matching the operator's explicit, literal request to eliminate per-field reconfirmation when applying a template. V2 fails the constraint outright; V3 satisfies the constraint but reintroduces exactly the friction the operator asked to remove, for no offsetting benefit -- fine-tuning stays available via Step 1's re-tune flow under either variant.


**Invariants:**
- The full template profile is always shown to the author before anything is saved, and the author always has an explicit opportunity to change it -- never silently adopted
- Behavior is identical between /ps-voice and /ps-style
- Step 1's existing re-tune flow for already-saved profiles is unaffected by this change

## 3. Rationale

**Counterargument:** A single combined confirmation is a coarser safety check than a field-by-field walkthrough -- an author skimming a long profile in one pass is more likely to miss a specific wrong field than one who was asked about it individually. This decision accepts that risk in exchange for the lower friction the operator explicitly asked for, betting that showing the full profile up front (not after) is enough review surface.

**Selected variant weakest link:** If the author gives a vague change request ('change the tone a bit') with no further detail, the agent must judge how much clarifying follow-up is appropriate without sliding back into a full re-interview -- a real but bounded judgment call, not a structural gap.

## 4. Consequences

**Rollback plan:**
Triggers:
- Authors start reporting saved profiles containing a field they didn't actually want, discovered only after the fact -- evidence the single combined confirm is too coarse a review surface
- The single show-and-confirm step itself becomes a place where the agent drifts back into asking field-by-field questions despite the instruction, mirroring the earlier checklist-formatting regression
Steps:
1. If mismatches surface: strengthen the single-step prompt to explicitly call out fields most likely to need attention (e.g. highlight anything that differs from a truly generic default) rather than reverting to full per-field walkthrough
2. If the agent drifts back to per-field questions: apply the same fix already used for the numbered-checklist regression -- a standalone bolded imperative rule plus a matching What-NOT-to-do entry, in both skills
Blast radius: cmd/pysar/assets/claude/skills/ps-voice/SKILL.md (Step 1a), cmd/pysar/assets/claude/skills/ps-style/SKILL.md (Step 1a) -- prompt-only, no schema or tool changes

**Affected files:** cmd/pysar/assets/claude/skills/ps-voice/SKILL.md, cmd/pysar/assets/claude/skills/ps-style/SKILL.md
