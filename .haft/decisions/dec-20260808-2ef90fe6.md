# One umbrella DRR: shared pipeline substrate + stage file contract

## 1. Problem Frame

**Signal:** haft check / coverage: Go modules implementing the shipped editorial pipeline are blind (no DecisionRecord): internal/intake, internal/research, internal/draft, internal/staffedit, internal/sharpen, internal/seo, internal/humanize, internal/export, plus internal/validation. Code and ps-* skills are live on master and released in v0.1.0; only a2a24f32/ffbfb04b cover the naming/Pass substrate. Operators developed past haft, so the graph under-governs the real system. Existing backlog prob-20260725-f12a3c92 covers research only.

**Constraints:**
- Do not invent alternate architectures — reverse-govern what master already ships
- Transformer Mandate: variants via /h-explore, binding via manual /h-decide
- Prefer one portfolio that can yield multiple DRRs (or one umbrella + module notes) over eight disconnected freestyle chats

**Acceptance:** Each of the listed pipeline modules is referenced by at least one active DecisionRecord (or an explicit deprecate/out-of-scope note) whose invariants match current code behavior; haft check coverage gaps for those modules are cleared; research backlog prob-20260725-f12a3c92 is either addressed by the same cycle or explicitly linked.

## 2. Decision

**Selected:** One umbrella DRR: shared pipeline substrate + stage file contract

**Selection policy:** Minimize reverse-governance ceremony while clearing module blindness for shipped code; prefer one substrate DRR over per-pass DRR inflation or coverage-only affected_files retagging; declare before scoring that pass-specific forks already decided elsewhere (e.g. seo-before-humanize) stay separate and are not absorbed into the umbrella.

**Why selected:** Operator explicitly bound V1. A single DecisionRecord reverse-governs the shared facts already true on master: Pass/Precondition registration, one revision artifact per stage, shared draft helpers/MCP resolveAnchoredPass, and validation as the shared error surface — clearing blindness for intake/research/draft/staffedit/sharpen/seo/humanize/export/validation without nine parallel ceremonies.


**Invariants:**
- Editorial stages register as Pass implementations with Precondition in internal/editorial (not ad-hoc skill-only sequencing)
- Each stage that revises prose writes its own artifact file under the piece directory (draft.md, staff-edit.md, sharpen.md, seo.md, humanize.md, plus intake/research/export artifacts as coded) — stages do not overwrite prior stage files in place
- Shared write/validate helpers live in internal/draft (and internal/validation for shared check errors); stage packages do not reimplement citation validation
- MCP tools reach pieces via shared resolveAnchoredPass (or equivalent), not per-tool path invention
- Pass-specific decisions already recorded elsewhere (notably seo-before-humanize) remain authoritative for those forks and are not silently overridden by this umbrella
- This DRR reverse-governs shipped behavior; it does not authorize redesign of the pipeline

**Pre-conditions:**
- [ ] prob-20260808-eb6fb84e and sol-20260808-8d058962 exist
- [ ] Pipeline packages already shipped on master / v0.1.0

**Post-conditions:**
- [ ] affected_files of this DRR include the previously blind pipeline packages
- [ ] prob-20260725-f12a3c92 is linked as addressed by this substrate coverage unless a later pass-specific research DRR supersedes that link
- [ ] Baseline snapshot taken for drift detection

**Admissibility:**
- NOT: Using this DRR as license to invent a new pipeline architecture
- NOT: Deleting per-stage artifact files in favor of a single mutable draft without a new decide
- NOT: Counting coverage-only affected_files retags on unrelated DRRs as satisfying this decision

## 3. Rationale

**Counterargument:** V3 (substrate DRR + Notes per package) is more proportional for package-local facts and avoids junk-drawer pressure on one DRR — V1 may recreate the original gap inside a single oversized artifact.

**Selected variant weakest link:** Pass-specific policy (research tier floors, intake provisional naming, humanize scope exclusions) is thinner than a per-pass DRR set; future stage-only changes may reopen the umbrella repeatedly or drift undocumented again if operators treat the umbrella as complete local memory.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| One umbrella DRR: shared pipeline substrate + stage file contract | **Selected** | Operator explicitly bound V1. A single DecisionRecord rev... |
| Per-pass DecisionRecords reverse-extracted from each package | Rejected | Ceremony cost too high for reverse-governance of already-shipped isomorphic Pass packages; invites copy-paste invariant rot. |
| Substrate DRR + Notes (or micro-decisions) per blind package | Rejected | Uncertain whether Notes clear this project's coverage/require_decision tooling; operator chose binding DRR coverage over that bet. |
| Extend existing DRRs affected_files/baselines only — no new pipeline decisions | Rejected | Goodhart on coverage metrics without stating substrate invariants — fails acceptance if invariants must match code behavior. |
| Spec-section carriers for pipeline modules, DRRs only on forks | Rejected | Spec-only may not satisfy require_decision/coverage for package edits in this repo's workflow. |

**Evidence requirements:**
- Coverage/check output showing modules no longer blind
- go test green on pipeline packages post-decide

## 4. Consequences

**Rollback plan:**
Triggers:
- Coverage remains blind after baseline — umbrella did not attach to modules
- Umbrella is constantly reopened for unrelated pass edits
- Operator chooses to switch to per-pass or Notes model
Steps:
1. Supersede this DRR with the replacement portfolio choice
2. Restore or leave package Notes/DRRs as decided in the replacement
3. Re-baseline affected_files on the replacement
Blast radius: .haft graph only unless a mistaken code change was made; this decide is governance-only

**Refresh triggers:**
- A stage gains policy that contradicts the umbrella invariants
- Umbrella accumulates unrelated pass-specific rules (junk-drawer signal)
- Coverage tooling still reports those modules blind after baseline
