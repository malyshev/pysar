# Shared principle + explicit pre-ship self-check + targeted regression tests

## 1. Problem Frame

**Signal:** This session repeatedly shipped noisy or pointless output from two surfaces Pysar itself produces for its own end users -- not Claude's own chat replies to the operator during development, which CLAUDE.md's existing Communication style section already governs. (1) CLI messages in cmd/pysar/main.go: fixed 3 times (raw path leakage, "already exists" read as an error, "differs" messages with no actionable info -- note-20260719-d883dd47, note-20260719-82ea61c0). (2) ps-voice/ps-style skill conversational output: fixed 3 times this session (dumping all Step 2 questions as one numbered list despite an explicit written prohibition, Step 6 firing a pointless "save a template of the template you didn't change" question, and after fixing that, Step 6 explaining its own skip instead of staying silent -- note-20260719-4638efd7, note-20260719-7ca22cda). Each fix was reactive, caught only via live operator testing, never proactively. Operator wants a structural gate against this recurring, not another one-off reactive patch.

**Constraints:**
- Must be distinct in scope from CLAUDE.md's existing Communication style section, which governs Claude's own chat replies to the operator during development, not what Pysar itself ships to its own end users via CLI or ps-* skills
- Must address both surfaces Pysar produces: static CLI output (directly testable) and agentic skill-prompt-governed live conversational output (not directly testable pre-runtime, since it is LLM-generated at conversation time, not static text in the repo)
- Must not be purely aspirational documentation alone -- already effectively tried once via existing prose guidance on an adjacent surface, already shown insufficient
- Reversible, low blast radius -- process/documentation plus at most a small test addition, not a schema or architecture change

**Acceptance:** A concrete, reusable mechanism exists that: (1) is checked before any new/changed CLI message or skill conversational instruction is considered complete; (2) names the specific noise patterns already caught this session as concrete negative examples; (3) is a single source of truth that ps-* skills and future CLI message work reference, rather than each surface re-deriving its own rules ad hoc (as has happened 3 times, inconsistently, this session); (4) includes at least one genuinely testable/checkable component, not purely aspirational prose alone -- since CLAUDE.md's existing prose guidance for a related surface (Claude's own chat replies) already did not prevent 3 recurrences on these two adjacent surfaces this session.

## 2. Decision

**Selected:** Shared principle + explicit pre-ship self-check + targeted regression tests

**Selection policy:** Pareto front over target-role dimensions (covers_both_surfaces, single_source_reuse), gated by the constraint (has_testable_component) which must hold true; new_maintenance_overhead is observation-role, watched but never optimized (Anti-Goodhart) and does not itself break a Pareto tie. Declared before scoring (sol-20260719-89dcc679).

**Why selected:** V3 and V4 tie on both declared targets (covers_both_surfaces, single_source_reuse), so this is a judgment call, not a forced conclusion. V3 achieves everything V4 does on the dimensions declared to matter, at lower ongoing maintenance cost -- no new .haft spec file to keep cross-referenced, no broader generic CLI pattern test whose recall against genuinely novel phrasing is structurally weak (every incident this session used different specific wording than the last). V4's extra weight buys no additional coverage this comparison's own dimensions show as real.


**Invariants:**
- The shared message-discipline principle lives in exactly one place (CLAUDE.md); ps-voice and ps-style reference it, neither re-derives its own version
- The principle names concrete negative examples from this session's real incidents, not only abstract advice
- This decision does not claim to machine-enforce the agentic-surface half -- that gap is explicitly acknowledged in the decision record, not hidden

## 3. Rationale

**Counterargument:** This decision leaves enforcement of the surface with the majority of this session's real recurrences (agentic skill-prompt output -- 2 of 3 incidents) entirely dependent on a future session's own discipline in applying the self-check, with no mechanism stopping a recurrence beyond that. This is precisely the same failure mode already observed for the existing Communication-style prose in CLAUDE.md, which also relied on the agent remembering to apply it and was skipped 3 times this session regardless. If a 4th incident happens, this decision alone will not have actually prevented it -- only made the fix faster to apply once caught.

**Selected variant weakest link:** The agentic-surface half of has_testable_component is a self-check the agent applies to itself, not machine-enforced -- a real, unresolved gap, not a solved problem. This was V3's own stated weakest_link at exploration time.

## 4. Consequences

**Rollback plan:**
Triggers:
- A 4th noise/verbosity incident occurs on the agentic surface and is caught only by the operator's live testing, not self-caught -- direct evidence the self-check alone is insufficient enforcement
- The shared CLAUDE.md principle drifts out of sync with what ps-voice/ps-style actually reference, or a future new ps-* skill is written without referencing it at all
- The targeted regression tests prove too narrow to catch even close variants of the 3 known incidents (e.g. a slightly reworded version of the same underlying CLI message)
Steps:
1. If a 4th agentic-surface incident is operator-caught rather than self-caught: revisit this decision and consider V4's or a stronger mechanism specifically for that surface -- this is the honestly-flagged gap this decision did not claim to close
2. If the principle drifts out of sync: fix the specific skill file's reference, and treat repeated drift as evidence for V4's spec-file approach instead
3. If regression tests prove too narrow: broaden them incrementally to cover the near-miss variant, not a wholesale shift to V4's generic pattern-matching approach unless multiple such gaps accumulate
Blast radius: CLAUDE.md (new section), cmd/pysar/assets/claude/skills/ps-voice/SKILL.md and ps-style/SKILL.md (reference the shared principle), cmd/pysar/init_test.go (regression tests) -- documentation and test-only, no schema or architecture change

**Affected files:** CLAUDE.md, cmd/pysar/assets/claude/skills/ps-voice/SKILL.md, cmd/pysar/assets/claude/skills/ps-style/SKILL.md, cmd/pysar/init_test.go
